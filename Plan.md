**Plugin option**: Install "Git" plugin in Obsidian (Settings → Third-party plugins) to commit from within Obsidian. Keep it simple by default and use the CLI for better control.

## 5. Continuous Writing Workflow

### 5.1 Daily session routine

```
1. git pull --ff-only      # get others'/your latest changes
2. Open Obsidian vault
3. Write the next chapter section in a draft note
4. Save; close Obsidian
5. git add -A
6. git commit -m "<type>: <desc>"
7. git push origin main
```

### 5.2 Commit messages (conventional-ish style)

| Type | Use for |
|---|---|
| `feat:` | New chapter / translation start |
| `chore:` | Skeleton, config, README updates |
| `fix:` | Corrected translation, typo fix |
| `docs:` | Plan.md, README, glossary updates |
| `refactor:` | Restructuring, renames |

Examples:

```text
feat: add chapter 02 draft
fix: correct verb conjugation in ch01-217
chore: update glossary and style guide
```

### 5.3 Branching strategy (optional but recommended)

```
main                # stable, publish-ready snapshots
├── feature/02-en-hans       # new chapter work (branch off main)
├── review/03-kor-en         # review pass over main
└── release/v0.1             # snapshots you want to pull from
```

```bat
git checkout main
git pull --ff-only
git checkout -b feature/02-en-hans
# write, commit, push
git push -u origin feature/02-en-hans
```

Merge back when the chapter is review-ready:

```bat
git checkout main
git pull --ff-only
git merge feature/02-en-hans
git push origin main
```

## 6. Continuous Development / Maintenance

### 6.1 Revision log (`notes/progress.md`)

Maintain a living log so you (and any collaborator) can see what changed and why:

```markdown
# Progress Log

## 2026-11-03
- Drafted Chapter 01 opening, 4 paragraphs
- Created glossary with 12 terms
- Fixed punctuation error in ch01-217

## 2026-11-04
- ...
```

### 6.2 Glossary & style guide

- `notes/glossary.md` — term → preferred translation, with source context.
- `notes/style-guide.md` — register, tone, punctuation rules, consistency constraints.

### 6.3 Review workflow

1. Draft to `translation/`.
2. Create a review branch off `main`.
3. Read aloud / back-translate to check fidelity.
4. Update `notes/progress.md`, leave inline comments in the Markdown.
5. Merge into `main` only when the review is complete and you are satisfied.
6. Tag release snapshots: `git tag -a v0.1 -m "Chapter 01 review complete"`

### 6.4 Tagging & releases

```bat
git tag -a v0.1 -m "v0.1: ch01 review-ready"
git push origin v0.1
```

### 6.5 Large project tricks

- **Deterministic ordering**: write chapters in order, or use a `master-plan.md` task list that maps chapter numbers to status.
- **Branch per chapter** if you are mid-scene or the translation is heavily revised: `feature/ch03-v2`.
- **Restore any past state**: `git log --all --oneline -- translation/` then `git checkout <commit> -- translation/ch03.md`.

## 7. Backup & Resilience

| Layer | How |
|---|---|
| Local git | `git push` after every meaningful session |
| Remote GitHub | main + feature branches |
| Overhead | Keep a copy of `source/` (original text) separate from your translations |
| Obsidian | Obsidian itself auto-saves; keep `obsidian/.trash` from being committed |

**Golden rule**: never rely on a single file. The repo + GitHub + your source copy is your backup chain.

## 8. Conflict & Recovery

### Merge conflict on a chapter

```bat
git pull origin main
# resolve the conflict in the file (search for <<<<<<<, >>>>>>>)
git add <file>
git commit -m "fix: resolve ch01 conflict with upstream"
git push origin main
```

### Accidentally lost work

```bat
git reflog          # find the commit hash before the loss
git show <hash> --stat
git checkout <hash> -- <file>
```

### Reclaim a polluted working tree

```bat
git status          # what is untracked?
git clean -nd       # dry-run what would be deleted
git clean -f        # actually remove untracked junk
```
